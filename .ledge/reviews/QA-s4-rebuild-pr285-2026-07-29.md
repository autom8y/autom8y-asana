## VERDICT: **NO-GO** (one HIGH prod-truth wound through the fully-public flow; fix is S4-local and cheap)

The stage-validate-swap *ordering* is real and well-toothed (C9 miswire canary has two-sided teeth;
mid-abort byte-identity holds; RC-E-4 AST import guard bites). The wound is not the ordering — it is
**which proof gets published**: the byte-changed swap path publishes the version's **first-stage
immutable metadata proof**, while every guard (C12 monotonicity, [H13] validate, the C9 receipt)
examined the **in-memory** staged proof. The two diverge whenever content **recurs** — and then the
pointer's freshness truth regresses (P1), races regress it further (P4), and a **rejected** staging's
poisoned proof becomes servable and *uncurable* (P3). The TDD §11 C14 ruling's sentence "the normal
`swap_pointer` path (byte-changed / first publish) is correct as-is (staged metadata IS the rebuild
proof there)" is **falsified** for the recurrence case — metadata is the rebuild proof only for the
*first* staging of a version_id.

## F1 — [HIGH · WOUND-CONFIRMED · public flow] Byte-changed swap publishes the FIRST-stage metadata proof, not the validated one → pointer regression AND uncurable future-proof false-serve

**Mechanism** (`rebuild.py:526-534` + `store.py:371` `swap_pointer` → `_staged_proof` reads version
metadata; `store.py:345-347` `stage_version` 412-swallow never rewrites metadata): C12 compares
`staged.proof.built_from_live_at` (in-memory, validated) against current, then `swap_pointer`
publishes whatever proof the version's immutable metadata has carried **since its first-ever
staging**. Three executed manifestations:

- **PROBE-P1 (regression, zero adversarial input)** — content reversion A→B→A with honest instants:
  rebuild A@T0 → rebuild B@T2 → rebuild A-again@T3. Verbatim:
  `P1: outcome=swapped result.built=2026-07-29 13:00 LIVE pointer.built=2026-07-25 10:00` —
  the pointer proof **regressed T2 → T0** (4 days), below the incumbent, while the `RebuildResult`
  over-reports T3. Violates the C12 obligation ("must never regress the pointer") in the freshness
  plane and the `RebuildResult` contract ("describe the LIVE artifact"). Serve-side direction:
  over-refuse (STALE) until the next same-content warm C14-cures it — a one-cadence availability
  outage per reversion event, plus a falsified S8 receipt.
- **PROBE-P3 (false-serve, uncurable, 100% public flow)** — the *discarded staged version's proof
  becomes servable*: (1) a clock-skewed fetch of content A reports future instants → validate
  **correctly REJECTS** (`proof-well-formedness`) — live untouched, RC-E appears to hold — but the
  rejected staging already wrote version X with a **FUTURE metadata proof** (immutable, permanent);
  (2) a later fully-honest rebuild of the same bytes at T3 passes validate and byte-changed-swaps →
  `LIVE built=2026-07-30 09:00` — the **future proof is published**; `is_provable(now)=PROVABLE`
  at negative age → **PROVABLE forever** (the exact F8 hazard [H13]-check-3 exists to prevent);
  (3) the cure is **blocked**: every subsequent honest rebuild of the same content hits the C14
  branch and declines (`same version, staged proof older than current` — honest instants can never
  exceed the future incumbent). Corruption persists until the content itself changes. This is
  prod-truth corruption reached with no private API, no forged receipt, no store subclass —
  **RC-E's headline claim is falsified**.
- **PROBE-P4 (three-writer race)** — C14 refresher of X racing a new-version swapper landing Y@T2:
  the store's N1 guard fires `ProofDigestMismatch`, the rebuilder's re-branch (`rebuild.py:519-521`)
  correctly re-reads and byte-changed-swaps back to X (freshness-legit: X re-verified at T3 > T2) —
  but publishes X's T0 metadata proof: `LIVE built=2026-07-25 10:00` — regressed below both the
  racing winner's T2 and the rebuilder's own verified T3.

**Root cause (one sentence)**: the monotonicity/validation checks and the publish operate on
**different proof objects** whenever `version_id` pre-exists; nothing reconciles them.
**Fix direction (S4-local, no frozen-signature change — PE's choice of mechanism)**: after winning a
byte-changed `swap_pointer`, re-read the pointer and, if the published proof differs from
`staged.proof` (staged fresher), immediately `refresh_pointer_proof` forward under CAS (the C14 op
already enforces same-digest + forward-only); additionally decline the swap when the version's
metadata proof would regress the incumbent. This also structurally kills the P3 poison (the honest
staged proof always overwrites the poisoned metadata proof at publish). Add P1/P3/P4 as regression
tests — none of the 25 landed tests exercises a **pre-existing version under a byte-changed swap**.

## F2 — [MEDIUM · construction-integrity] C9 ValidationReceipt under-binds: version_id only — the validated PROOF is not what the receipt attests

**PROBE-P2**: mint an honest receipt for staged(X, proof@T2); construct a same-bytes
`StagedVersion(X, proof@FUTURE)` (same `content_digest`, so the store's N1 guard passes);
`_publish(aid, evil, receipt)` → `live built=2026-07-30 09:00`, `is_provable=PROVABLE` — the C14
refresh path (`rebuild.py:507`) publishes the **in-memory, never-validated** proof verbatim.
**PROBE-P2b**: a receipt with `content_digest="not-a-digest"` is accepted — `_publish` checks only
`receipt.version_id` (`rebuild.py:482`); the receipt's own `content_digest` field is dead weight.
Asymmetry worth naming: on the **swap** path the store's metadata wins (in-memory tampering is
ignored — and F1 is the dark side of that); on the **refresh** path the in-memory proof wins
(validation is bypassable). Not reachable via public `rebuild()` alone (requires `_publish` access —
the same altitude the landed C9 miswire canary already models), so MEDIUM not HIGH — but the module
docstring's "un-bypassable key" claim is overstated. **Fix**: bind the receipt to the full proof
(`content_digest` + `built_from_live_at`, or a proof hash) and check the whole binding in `_publish`.

## F3 — [MEDIUM · silently-smaller frame] Default population floor is absolute (`min_rows=1`) — a 99.8% shrink replaces a healthy artifact

**PROBE-P5**: healthy 500-row artifact live; a partial-but-nonempty 1-row fetch with fresh instants →
`outcome=swapped; served rows now=1 (was 500)`. `FetchRefused`-on-partial is the fetcher's
**unverifiable** obligation (the frame carries no section identity); the shipped default predicate is
the only net and it cannot catch shrink. 0-row and null-value floors DO bite (landed tests + re-run);
`min_rows=0`/negative is unguarded (caller misconfig → empty publish). **Disposition**: predicates
are injectable by design — but the DEFAULT is the shipped surface. Recommend a relative shrink guard
(vs incumbent row count) or an explicit architect ruling accepting absolute-floor semantics for the
epoch, plus a `min_rows >= 1` constructor guard.

## F4 — [LOW-MEDIUM · drawn-contract trust boundary · disclose] MIN-fold folds over the fetcher-REPORTED instant set only

**PROBE-P6b**: a frame materialised from sections {a,b} with instants reported only for `section-a` →
`SWAPPED built=T3` — whole-frame freshness claimed from one section's instant. Under-coverage
inflates freshness (C1's honest-aging inverts); over-coverage is conservative (MIN drags older).

## F5 — [LOW · efficiency guard only] [H12] single-flight duplicates under owner cancellation

**PROBE-P7b**: cancel the owner while parked in fetch → the `finally` (`rebuild.py:367-370`) pops the
key while the orphaned task still runs → a third caller re-executes: `fetch executions=2`. Correctness
is unharmed (store CAS is the invariant); the pacing/efficiency guard [H12] is what weakens, and the
orphaned task's result is never retrieved. **PROBE-P7a** (good): coalesced waiters receive the
owner's mid-gather failure LOUD — `owner=RuntimeError, waiter=RuntimeError, fetches=1` — no hang.

## F6 — [LOW · S8-receipt truthfulness] RebuildResult field-contract and outcome nondeterminism at the same end-state

**PROBE-P8a**: monotonicity-decline `STAGED_REJECTED` carries the **incumbent's**
`version_id`/`built_from_live_at` while the dataclass docstring says "`None` when nothing was
published" (`rebuild.py:132-135`) — docstring false; an S8 consumer could misread the field as the
staged version. **PROBE-P8b**: the `StaleProofRefused` accept-done path returns `SWAPPED` with

(`validation failed [...]` vs `monotonicity decline: ...`) ARE stable disambiguators — keep them
frozen for S8. **Fix**: correct the docstring; on accept-done paths report the re-read live proof.
