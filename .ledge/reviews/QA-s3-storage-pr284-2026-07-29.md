## What holds (adversary could not break it)

- **CAS is a true CAS, two-sided.** 3-contender race on one ETag → exactly **1 winner, 2 `CASLost`** (PROBE-P1). Concurrent first-ever creators on `CREATE_IF_ABSENT` (`If-None-Match:*`) → exactly **1 creator wins** (PROBE-P2). Stale-ETag swap → `CASLost` (landed). No silent last-writer-wins clobber — the C3 tooth bites.
- **Immutability by construction.** VersionId = `sha256(frame_bytes)`; distinct content cannot address a pointed-to key; re-stage of identical bytes is `If-None-Match:*` 412-swallowed and never rewrites the frame (landed). The served frame is byte-for-byte stable across a partial stage of new bytes.
- **Absence + dangling are LOUD.** Empty store → `ArtifactMissing` (never `(None,None)`, the v1 wound) ([H5]). A pointer naming a reaped frame → `ArtifactMissing`, not silent (landed). Even a swap/gc **TOCTOU** that constructs a dangling pointer (gc reaps the frame between swap's proof-HEAD and the pointer-PUT) fails loud on the next `read_current` (PROBE-P9).
- **Rollback is honest.** Re-pointing an OLDER version serves its OLD bytes with its OLD proof — no freshness laundering (PROBE-P6). ([H6] monotonicity placement is already architect-routed per dispatch note; store behavior under rollback is correct.)
- **Swap-to-unstaged is refused.** `_staged_proof` HEAD 404 → loud `ValueError` — you cannot swap to a never-staged VersionId (landed). A dangling pointer is only constructible via a concurrent-reap race, and it is loud on read (PROBE-P9).
- **Conformance intact.** Frozen Protocol signatures (`read_current`/`stage_version`/`swap_pointer`/`list_versions`/`gc_versions`) unchanged vs origin/main; **exports still 24**; no sibling seam bodies edited (freshness/serve/observe/rebuild untouched); **RC-A subtraction confirmed** — grep finds NO dual-read / legacy-fallback / second-layout / `SUNSET_AFTER` code path in either module (only docstring mentions). C11 holds.
- **Dark-build key isolation HOLDS.** `dataframes-v2/` and v1 `dataframes/` are **empirically disjoint** under slash-anchored prefix listing (moto probe: v1 lister sees 0 v2 keys, v2 lister sees 0 v1 keys). The only token that spans both is a bare no-slash `"dataframes"` prefix, and **zero v1 S3 listers use it** (the sole bare-token hit is an HTTP route `/api/v1/dataframes`, not an S3 key). The dark-build guarantee is real.

## Findings (routed)

### F1 — [HIGH · design/availability · correctness-SAFE] Freshness cannot advance for byte-stable content — route ARCHITECT before cutover-lock

**PROBE-P5 (WOUND-CONFIRMED).** `stage_version` freezes the FIRST proof into the version's immutable S3 metadata; on a re-stage of identical bytes the 412 path `return version_id` **without rewriting metadata**. `swap_pointer` then publishes the proof it reads back from that staged metadata (`_staged_proof`), **not** the caller-supplied proof. Consequence: two rebuilds of *byte-identical* content at t0 and t1 mint the same VersionId → the second (fresher) `built_from_live_at=t1` is silently discarded; the served pointer carries **t0**. Receipt: content re-verified fresh at t1, served age = 21600s > sla 3600s → the artifact **STALE-refuses** every cycle despite live re-fetch confirming freshness.

- **Direction ruling (the prompt's question):** this is a freshness **UNDERSTATEMENT** — served `built_from_live_at` is OLDER than the true last-fetch instant, so `is_provable` can only OVER-refuse (false STALE), never UNDER-refuse (false PROVABLE). It is **NOT** the overstatement WOUND-CLASS. **Correctness-safe.**
- **But** it converts to a **permanent availability wound** for byte-stable entities: a business/offer whose data is genuinely stable across an SLA window can never advance its served proof — no path (stage's 412-swallow OR swap's staged-metadata read) lets a fresher proof reach `current.json`. This is a production failure mode that would surprise (the acid test): a healthy, live-re-verified artifact refuses forever.
- **Why it is a STORE finding in THIS PR:** DP-2 Option C's whole rationale is that the pointer (mutable) carries proof *separately* from the immutable version; the implementation re-couples proof to content-identity by sourcing it from version metadata. This contradicts C1/[H3] ("a section's fetch-instant advances on every real content fetch"). The remediation is store-owned: either `swap_pointer` publishes the caller-supplied fresh proof into the pointer (Option C makes this atomic — the pointer IS the one mutable object), or re-stage refreshes metadata. **Adjudicate before the one-way door locks.** Distinct from the architect-routed [H6] monotonicity question — do not conflate.

### F2 — [MEDIUM · defensive · one-way-door hardening] Blank `if_match` degrades to an UNCONDITIONAL overwrite — route PE + S8

**PROBE-P12 (finding-assert fired).** `swap_pointer` translates any non-sentinel `if_match` into `IfMatch=str(if_match)` with no validation. `ETag("")` → `IfMatch=""`, which **under moto is treated as no-precondition and the pointer is clobbered unconditionally** (probe: `empty-etag=SWAPPED(unconditional!)`, `live=MOVED`) — the exact concurrent-clobber the shape exists to forbid. A garbage ETag correctly `CASLost`.

- **Reachability:** `read_pointer` always returns a populated ETag and `CREATE_IF_ABSENT` is the sentinel, so a blank `if_match` arises only from caller misuse — but on a load-bearing one-way-door CAS, a one-line guard (reject blank/whitespace non-sentinel `if_match`, or refuse to emit `IfMatch=""`) closes the class cheaply.
- **S8 carry:** real-S3 behavior of `If-Match: ""` is **unverified** (moto degraded to unconditional; real S3 likely `400 InvalidArgument`). Either way the store should never emit `IfMatch=""`.

### F3 — [MEDIUM · defensive · path-traversal] `project_gid` charset is unguarded → cross-artifact keyspace nesting — route PE

**PROBE-P7 (WOUND-CONFIRMED) + PROBE-P8.** The [H4] guard validates emptiness + servability but **not `project_gid` charset**. A slash-bearing gid (`"1200/offer/versions/deadbeef"`) builds a traversal key that nests one artifact **inside** another's version keyspace: the phantom version `deadbeef` leaks into the **victim's** `list_versions`, AND the **victim's `gc_versions` reaps the hostile artifact's frame** (cross-artifact destruction — probe: hostile artifact destroyed by another artifact's gc = True). PROBE-P8: `object.__new__` + `pickle`/`deepcopy` construct un-guarded instances carrying a traversal gid + UNKNOWN entity (`dataclasses.replace()` and `__init__` ARE guarded; pickle/copy are not).

- **Reachability:** production `project_gid`s are numeric from the trusted entity-registry / workspace-discovery, so weaponizing needs upstream injection — **LOW live risk**. But on a one-way door a gid-charset guard (digits-only, or minimally reject `/`) is cheap defense-in-depth, and it also hardens the pickle/`__new__` bypass surface.

### F4 — [MEDIUM · scalability · latent] `list_versions` / `gc_versions` are un-paginated (1000-key cap) → unbounded version tail — route PE

**PROBE-P10 (WOUND-CONFIRMED).** Both use a single `list_objects_v2` (1000-key hard cap). 1002 staged versions → `list_versions` returns **1000**; `gc_versions` shares the cap, so the tail beyond page 1 is never enumerated → never reaped → unbounded accumulation once a hot artifact exceeds 1000 retained versions. The gc protected-set (current + current-1) is also computed only over the visible page. Reachability depends on churn vs GC cadence; SLA+grace GC normally keeps counts low, but a high-churn artifact or a stalled GC crosses 1000. **Paginate both.** SRE-relevant.

### F5 — [LOW · taxonomy] Corrupt pointer raises raw `JSONDecodeError` / `KeyError`, not a store-taxonomy exception — route PE

**PROBE-P3 / P4.** A truncated or schema-incomplete `current.json` raises bare `json.JSONDecodeError` (P3) / `KeyError('proof')` (P4) from `read_pointer`/`read_current`. It **is loud** (no silent None → satisfies [H5] in spirit), but Seam-4 catches `ArtifactMissing` to map to `Refused(MISSING)`; a bare `JSONDecodeError` may escape that handler and surface as a 500 rather than a clean refusal. Recommend a `PointerCorrupt(PointerCASError)` (or fold into `ArtifactMissing`). Low severity — a corrupt pointer requires external tampering (S3 writes are atomic, so a torn write cannot produce this), but the read-path taxonomy has a gap.

## Two-digest semantics (P13) — MEDIUM-LOW · doc/type hardening

Two **structurally identical** 64-hex strings now coexist per version and are **semantically distinct**:
`VersionId = sha256(frame_bytes)` (physical **address**, store.py:16) vs `FreshnessProof.content_digest = canonical_digest(...)` (parquet-**INDEPENDENT** freshness digest — freshness.py:35 "never GIDs, never parquet bytes"). The store is policy-free and accepts **arbitrary divergence** between them (PROBE-P13 stored `content_digest="f"*64` against a different address digest and served it). A consumer that uses the wrong one is a real drift class. The distinction is documented in prose but **not type-distinguished** (`content_digest` is a bare `str`, not a NewType) and not co-located. **Recommend** a doc/type note that address-digest != freshness-digest.

**Serialization-determinism coupling (S8/Seam-3 carry):** `sha256(frame_bytes)` is over PHYSICAL bytes, so two logically-identical frames with different physical serializations (parquet row-order / compression / nondeterminism) mint DIFFERENT VersionIds. The C3 **idempotency advisory therefore depends on byte-deterministic frame serialization**, which is Seam-3's `materialize`/`canonical_digest` job, not the store's. Interaction worth naming: if serialization is byte-deterministic, F1 (stuck freshness) bites; if it is non-deterministic, you instead get dup-version proliferation (feeds F4) and C3 idempotency becomes theater. **Verify the Seam-3 materializer is deterministic at S8**, else the store's idempotency guarantee is hollow.

## Conformance observation (not a defect)

`store.py` promotes `VersionId` / `ETag` from SEAM-0's transparent `type X = str` aliases to `NewType("X", str)`. This is **grant-sanctioned** (dispatch task-item 7), **strengthens** typing (a raw str / project_gid can no longer be passed where a version identity is required — no signature-shape change), and **all frozen signatures still typecheck** (mypy-strict clean + C6 slow mypy-receipt PASS). Named for the record; it is a tightening, not a break.

1. **`If-Match: ""`** degraded to an unconditional PUT under moto; real S3 unverified (F2).
2. **`409 ConcurrentPointerDelete`** — moto never synthesizes the concurrent-delete race; the landed test injects the 409 via `patch.object`. ## (b) NEW SURFACE — `refresh_pointer_proof(aid, proof, *, if_match)` (C14 / architect F1 ruling)

**What holds (attacked, could not break):**

- **Interleaving, both orders (attack 1).** Swap-lands-first: a refresh holding the pre-swap ETag → `CASLost`; pointer = swapped version B **with B's own staged proof** — an old version_id can NOT be republished over a fresher-swapped pointer (PROBE-R2-C14-1a). Refresh-lands-first: the swap holding the pre-refresh ETag → `CASLost`; the ratified re-read/retry converges on B (PROBE-R2-C14-1a-rev). The in-op re-read + caller-ETag CAS makes the op linearize correctly against `swap_pointer` in both orders.
- **F1 cure demonstrated end-to-end.** The round-1 P5 trap re-fired unchanged at the stage/swap layer (pointer carries t0 after a byte-identical restage at t1), then `refresh_pointer_proof` advanced the served proof t0→t1 for the SAME version — the stale-forever trap for byte-stable content is **curable at the store**; a strictly-backward refresh raises `StaleProofRefused` (PROBE-R2-C14-5).
- **Version-object immutability.** After refresh, the immutable frame's ETag AND metadata are byte-identical; only `current.json` changed (PROBE-R2-C14-6). Option-C decoupling (proof lives on the mutable pointer) is realized as ruled.
- **Absent pointer (attack 4).** Refresh on a never-swapped artifact → `ArtifactMissing`, loud (PROBE-R2-C14-4).
- **Equal-instant republish (attack 3).** Allowed per non-decreasing; and because the JSON body is byte-identical (`sort_keys`), S3's content-defined md5 ETag is UNCHANGED → the republish is **ETag-stable and idempotent at the CAS level** — no CASLost storm for concurrent ETag holders, cost is one redundant PUT (PROBE-R2-C14-3). S8 carry: on an SSE-KMS bucket ETags are not content-md5, so identical-body republish WOULD churn the ETag there — name it at integration.
- **Blank-`if_match` guard applies (attack 5).** Verified — builder's claim confirmed (PROBE-R2-F2).

### N1 — [MEDIUM-HIGH · NEW · fail-loud direction] Refresh does not validate proof↔version digest coherence — BLOCKING-BEFORE-S4-CONSUMPTION

**Two executed constructions:**

1. **Direct (attack 2):** a refresh with a fresher instant but a `content_digest` that does NOT match the pointed version was **ACCEPTED**: pointer proof digest `ee..` vs the version's immutable staged digest `aa..` (PROBE-R2-C14-2). The pointer now carries a proof that lies about the bytes.
2. **Realistic graft (attack 1's second-order):** refresher verifies bytes A fresh at t2; a swap A→B interleaves; the refresher's naive `CASLost`-remediation (re-read fresh ETag → re-fire the SAME proof) **republishes version B with the proof verified against A's bytes** — the CAS cannot catch this (the ETag is genuinely current); only a digest-coherence check would (PROBE-R2-C14-1b). This is the DP-2 "re-read → re-derive → retry" pattern applied WITHOUT the re-derive step, and nothing in the op's contract forces the re-derive.

**Direction ruling:** fail-loud, NOT silent-wrong. In both constructions the published `content_digest` cannot verify against the served bytes' canonical digest, so the Seam-4 gate (`is_provable` per the FROZEN Seam-1 contract: digest mismatch → CORRUPT) refuses every read — an availability wound of the C3 "self-inflicted outage" class, never a wrong-number serve. The freshness overstatement embedded in the grafted proof can never be SERVED (it dies at the digest check). Caveat named honestly: this loudness depends on S2 implementing `is_provable` per the frozen contract and Seam-4 gating every read — both TDD-mandated.

**Why not merge-blocking:** the op has **zero consumers at HEAD** (grep receipt: no reference outside `store.py` and its tests — S4 policy is the intended first consumer and S4 is not yet built); the wound terminates loud; the guard is store-local and cheap (`proof.content_digest == current.proof.content_digest` — zero extra I/O; or vs `_staged_proof` metadata, one HEAD, the stronger immutable root). **Registered condition: S4 MUST NOT wire `refresh_pointer_proof` until the digest-coherence guard lands**; the same guard mechanically refuses the cross-version graft. Routed to principal-engineer as the first S4 task item.
