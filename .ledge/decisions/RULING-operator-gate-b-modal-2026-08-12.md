# OPERATOR RULING — the shape's modal governs charter gate (b)

## The ruling (operator's words, verbatim)

> "adopt the shape's modal"

## What was in contention

An external rite-disjoint adversary (2026-08-12T16:35Z, self-attestation
MODERATE) found two competing treatments of charter core item 5 gate (b)
— *"anything a customer sees"* (`CHARTER…:55`) — inside two artifacts the
ignition kit names together as "the decision space":

- **Frame `:122-128` — the tripwire structure.** The customers limb is OUTSIDE
  as scoped today (internal board, no client-reachable delivery), discharged by a
  standing NAMED OBSERVABLE TRIPWIRE: it fires "the moment any delivery lands
  where a client can see it," at which point the work halts to the operator.
- **Shape `:368-374` — the modal.** The gate is NOT STATICALLY DECIDABLE because
  the follower set is mutable and not under our control; therefore treat the gate
  as firing.

The adversary ruled the modal **OVER-EXTENDED — "it proves too much"**, on two
grounds: (i) the identical argument applies to the `#account-health` Slack rail
the shape itself endorses, which the shape does not so rule; (ii) `CHARTER…:55`'s
own clause — *"Everything else — INCLUDING reversible decisions that set patterns
others will copy — runs autonomously"* — exists to refuse the "but it might
matter later" species of argument.

## The ruling and its effect

**The shape's modal GOVERNS.** Gate (b) is treated as firing on the Asana write
classes on mutable-recipient-set grounds. The frame's tripwire structure is
superseded as the governing reading and remains as the historical of-record.

The adversary's OVER-EXTENDED verdict is **overruled by operator word** — which
is the adjudicator's prerogative and is recorded as such, not as a refutation of
the critique. The critique stands in the record; the ruling stands over it.

**Practical effect: NONE on any outcome.** CR-1 reserved all three Asana write
classes and CR-2 reserved Mission B's access under BOTH readings. This ruling
settles WHOSE REASONING GOVERNS, which matters for coherence and for what future
seats may derive — not for what any seat may do today.

## ⚠ OPEN — the scope question this ruling does NOT answer

The adversary's first ground is a **consistency** objection, and adopting the
modal does not dissolve it. The `#account-health` Slack rail has the identical
property the modal keys on: a workspace admin can add a guest to that channel
exactly as an Asana admin can add a guest follower. Applied consistently, the
modal fires gate (b) on the Slack rail too — and the Slack rail is the ONLY
delivery rail verified live (frame SVR-1/3/4/5: iris unresolved, MCP write
surface exposure-gated OFF and stdio-only under a promotion fence,
comment-CREATE client-layer only).

**This is NOT recorded as decided in either direction.** Two readings remain
available and only the operator may pick:

- **(a) Modal scoped to Asana writes.** Gate (b) fires on board writes on
  mutable-follower grounds; the Slack rail is distinguished (opted-in shared
  channel, membership internally controlled, already carrying automated posts
  6×/day). Delivery via Slack stays autonomous.
- **(b) Modal applied uniformly.** Gate (b) fires wherever the recipient set is
  mutable — including `#account-health`. **Consequence: the only working delivery
  rail becomes operator-gated**, and every readout this initiative produces needs
  an operator release per publication.

**Routing:** this question belongs in the **PT-02 briefing** as a named decision
surface, alongside the CR-2 §6-T1 under-call. It does not block Sprint 1 — S1-S4
are read-only `.ledge/` work that uses no rail. It DOES bind S3, whose subject is
the rails: S3 must present both readings and must not assume either.
