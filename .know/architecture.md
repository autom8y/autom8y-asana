## Key Abstractions

Mental model: the **Asana SDK** (`AsanaClient` + resource clients + transport) is the base; **models/business** adds the domain hierarchy; **dataframes + cache + query + resolution** turn Asana projects into cached polars frames that routes and Lambdas serve; **persistence** is the write path; **automation/lifecycle/lambda_handlers** are scheduled and event-driven consumers; **substrate** and **trigger** are dark, contract-first additions beside v1.

### 1. SDK facade and transport
- **`AsanaClient`** (`client.py:98`): one object per token. Resource clients are lazy properties that construct a client with the shared `AsanaHttpClient` and shared `CacheProvider` (e.g. `tasks` `client.py:388`). Supports sync and async (`__enter__`/`__aenter__`, `close`/`aclose`).

Concrete clients (`clients/tasks.py` etc.) read cache, call `self._http.get/post/put/delete`, then write cache (`tasks.py:217,312,317`). `BatchClient(BaseClient)` (`batch/client.py:19`).
- **`async_method`** (`patterns/async_method.py:188`, `AsyncMethodPair` `:62`): generates the sync twin from an `*_async` coroutine; `SyncInAsyncContextError` guards misuse (`errors.py`).
- **`AsanaHttpClient`** (`transport/asana_http.py:91`): wraps `autom8y_http.Autom8yHttpClient`; owns a token-bucket rate limiter, circuit breaker, exponential-backoff retry (`:226-239`), and read/write **AIMD adaptive semaphores** (`transport/adaptive_semaphore.py`, wired `:163-217`). `ConfigTranslator` maps `AsanaConfig` to SDK configs; `AsanaResponseHandler` (`transport/response_handler.py:27`).
