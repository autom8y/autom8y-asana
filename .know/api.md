**Idempotency (opt-in store-and-replay): `src/autom8_asana/api/middleware/idempotency.py`.** `IDEMPOTENT_ENDPOINTS` is exactly four `(method, template)` pairs (`:62-69`): `POST /v1/intake/business`, `POST /v1/intake/route`, `POST /v1/tasks/{task_gid}/custom-fields`, `PATCH /api/v1/entity/{entity_type}/{gid}`. Backend selection happens in `create_app` from `IDEMPOTENCY_STORE_BACKEND` (`main.py:395-441`): default `noop` (`DEFAULT_IDEMPOTENCY_BACKEND`, `main.py:91`; PR #535) because the middleware sits outside `JWTAuthMiddleware` and so runs before authentication and cannot key on a verified principal (comment `main.py:403-406`; order established in the Layered chain, item 2); `dynamodb` (table `IDEMPOTENCY_TABLE_NAME` default `autom8-idempotency-keys`, region `IDEMPOTENCY_TABLE_REGION` default `us-east-1`; construction failure degrades to noop) and `memory` are opt-in; an unknown value degrades to noop with a warning. Protocol when a store is active: no `Idempotency-Key` header -> pass through (a derived fallback key is only logged); key must be 8-256 chars of `[A-Za-z0-9-_.]` else 400; two-phase `claim`; in-flight duplicate -> 409 `IDEMPOTENCY_KEY_IN_FLIGHT` with `Retry-After: 1`; same key with a different body fingerprint (SHA-256 of body) -> 422 `IDEMPOTENCY_KEY_MISMATCH`; a completed match replays the stored status/body with `Idempotency-Key`, `X-Idempotent-Replayed: true`, `X-Idempotent-Original-Time`; store outages pass the request through with `X-Idempotent-Degraded: true`. Store TTL 86,400 s (`DEFAULT_TTL_SECONDS`, `:92`). Note: these middleware-level errors are a flat `{"error": CODE, "message": ...}` shape, not the canonical envelope. The module docstring's "stack position" list (`:14-20`) and the `_get_service_name` docstring (`:474-504`) are stale: they place JWT before idempotency, the reverse of the runtime order.

## Request/Response Contracts

- **Success envelope.** `SuccessResponse[T]` = `{"data": T, "meta": ResponseMeta}`, where `meta` carries `request_id`, `timestamp` and optional `pagination`. The envelope types (`SuccessResponse`, `ErrorResponse`, `ErrorDetail`, `ResponseMeta`, `PaginationMeta`, `build_success_response`, `build_error_response`) come from the shared `autom8y_api_schemas` package and are re-exported at `src/autom8_asana/api/models.py:25-35` for backward compatibility. Routes build responses with `build_success_response(data=..., request_id=..., pagination=...)` (e.g. `api/routes/tasks.py:126`). `ExportsSuccessResponse` (`models.py:98`) is a typed `SuccessResponse[list[dict[str, Any]]]` carrying schema examples. `DELETE` and the section add/reorder operations return 204 with no body (`projects.py:343`, `sections.py:206,257,310`, `tasks.py:326`). Query rows nest a second envelope: `SuccessResponse.data` is a `RowsResponse{data, meta}` whose `RowsMeta` carries `total_count`, `returned_count`, `limit`, `offset`, `entity_type`, `project_gid`, `query_ms`, and honesty fields (`query/models.py:454-466,648+`).
- **Error envelope.** `ErrorResponse` = `{"error": {"code", "message", "details"}, "meta": {"request_id", ...}}`. Built by `_build_error_response` (`api/errors.py:64-89`) for handler-raised errors, by `raise_api_error(request_id, status, code, message, details=, headers=)` (`errors.py:92-133`, raises `HTTPException` whose `detail` is the envelope dict) and by `raise_service_error` (`errors.py:136-177`, status from `get_status_for_error`, `details` = the service error's `to_dict()` minus request_id/error_code/message). `http_exception_handler` (`errors.py:448-474`) passes a dict `detail` through unchanged and otherwise wraps as `{"detail": ...}` (the non-canonical shape; FastAPI-native 404/405 land here).
- **Exception-to-status mapping** (`register_exception_handlers`, `errors.py:778-833`): `NotFoundError` 404 `RESOURCE_NOT_FOUND`; `AuthenticationError` 401 `INVALID_CREDENTIALS`; `ForbiddenError` 403 `FORBIDDEN`; `RateLimitError` (Asana upstream) 429 `RATE_LIMITED` with `Retry-After` (default 60); `GidValidationError` 400 `VALIDATION_ERROR`; `ServerError` 502 `UPSTREAM_ERROR`; `TimeoutError` 504 `UPSTREAM_TIMEOUT`; `httpx`-layer `RequestError` 502 `UPSTREAM_ERROR`; `AsanaError` 500 `INTERNAL_ERROR`; typed API-layer errors `ApiAuthError` 401, `ApiServiceUnavailableError` 503, `ApiDataFrameBuildError`, `ApiError` use their own `code`/`status_code` (`core/api_exceptions.py:29-135`, re-exported by `api/exception_types.py`); `HTTPException` as above; `Exception` catch-all 500 `INTERNAL_ERROR` with no detail leakage. `fleet_error_handler` (`errors.py:677`, registered `main.py` after `SecurityHeadersMiddleware`) routes any `autom8y_api_schemas.errors.FleetError` subclass through `fleet_error_to_response`. SlowAPI's own limit-exceeded 429 is the stock SlowAPI body (see rate limiting above), distinct from the Asana-upstream 429. Service-layer mapping (`services/errors.py` `SERVICE_ERROR_MAP`, 13 entries): unknown entity/section/task and `EntityTypeMismatchError`/`EntityNotFoundError` 404; `InvalidFieldError`, `NoValidFieldsError` 422; `InvalidParameterError`, `EntityValidationError` 400; `ServiceNotConfiguredError`, `CacheNotReadyError`, `CacheNotWarmError`, `CascadeNotReadyError` 503; default is each error's `status_hint`.
- **Validation errors.** `register_validation_handler(app, service_code_prefix="ASANA")` (`main.py:581`, imported from `autom8y_api_schemas.validation`) makes `RequestValidationError` emit the canonical code `ASANA-VAL-001` (comment cites ADR-canonical-error-vocabulary D-01/D-03). Webhook-specific typed errors carry fleet wire codes: `ASANA-AUTH-002` (401), `ASANA-DEP-002` (503), `ASANA-VAL-002` (invalid JSON), `ASANA-VAL-003` (missing gid), `ASANA-VAL-004` (invalid task) (`webhooks.py:48-112`).
- **Route-level error codes (AST walk of every `raise_api_error(request_id, <int>, "<CODE>", ...)` in `src/autom8_asana/api/`; 57 distinct status/code pairs).** 400: `INVALID_PHONE_FORMAT` (intake_create, intake_resolve), `INVALID_QUERY` (matching), `FLEET_QUERY_VALIDATION`, `INVALID_ENTITY_TYPE` (admin), exports lower-case codes `malformed_predicate`, `unknown_entity_type`, `unknown_field`, `unknown_section_value`. 403: `INSUFFICIENT_PRIVILEGE`. 404: `UNKNOWN_ENTITY_TYPE`, `UNKNOWN_ENTITY`, `UNKNOWN_DATA_SOURCE`, `NO_SECTION_CLASSIFIER`, `SCHEMA_NOT_FOUND`, `FIELD_NOT_ANNOTATED`, `FIELD_NOT_ENUM`, `BUSINESS_NOT_FOUND`, `UNIT_NOT_FOUND`, `TASK_NOT_FOUND`, `WORKFLOW_NOT_FOUND`, `COMPANY_NOT_RESOLVED`. 409: `COMPANY_AMBIGUOUS`. 422: `EMPTY_FIELDS`, `INVALID_FIELD`, `MISSING_CRITERIA`, `MISSING_REQUIRED_FIELD`, `UNKNOWN_PROCESS_TYPE`, `UNKNOWN_RECEIPT_KIND`, `VALIDATION_ERROR`, `WORKFLOW_VALIDATION_FAILED`. 429: `RATE_LIMITED` (entity_write, intake_custom_fields: upstream Asana limit surfaced). 500: `MATCHING_ERROR`, `RESOLUTION_ERROR`. 501: `STRATEGY_NOT_IMPLEMENTED`. 502: `ASANA_UPSTREAM_ERROR`, `UPSTREAM_ERROR`, `IDENTITY_SUPPLY_BASIS_CONFLICT`, `STAGE_CENSUS_{TRUNCATED,EMPTY_CORPUS,FIELD_ABSENT,GID_DRIFT}`. 503: `ASANA_UNAVAILABLE`, `CACHE_NOT_WARMED`, `CACHE_NOT_INITIALIZED`, `CACHE_UNAVAILABLE`, `REGISTRY_NOT_READY`, `PROJECT_NOT_CONFIGURED`, `DISCOVERY_INCOMPLETE`, `INDEX_NOT_READY`, `CASCADE_NOT_READY`, `SUBTASK_OBSERVATION_FAILED`, `BUSINESS_VERIFY_FAILED`, `COMPANY_ID_FIELD_UNCONFIGURED`, `IDENTITY_SUPPLY_UNAVAILABLE`, `STAGE_CENSUS_UNCONFIGURED`. 504: `ASANA_TIMEOUT`, `WORKFLOW_TIMEOUT`. - **Non-canonical error shapes to remember.** (1) Idempotency middleware errors are flat `{"error": "<CODE>", "message": ...}` (`idempotency.py:612-624,676-704`).
